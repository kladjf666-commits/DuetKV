实现与主要文件
==============
P1:
  PhaseKV/kernels/quantize_triton.py：4-bit K/token、V/channel 分组量化与打包；
    直接读取 stride，FP32 生成码值，FP16 保存 scale/min，每字节只有一个 writer。
  PhaseKV/kernels/packing.py：新增 allocate_packed、quantize_pack_fast、
    quantize_pack_into；保留 quantize_pack 原参考函数及 KIVI 调用。
    CPU、2/8-bit、跨字节的奇数组边界、过大组走原 packed 量化；不解包冻结 KV。
    输入/输出视图显式校验；输出支持非连续但不重叠的 stride。
  注意：PyTorch CUDA 的“张量除以 CPU 标量”实际采用 FP32 reciprocal multiply，
    因此 scale 的实现匹配该操作；码值的张量除法使用 correctly-rounded div_rn。
    这不是另加近似倒数。真实 CUDA 字节等价仍必须通过测试，失败不能放宽容差。
    核对来源：https://github.com/pytorch/pytorch/blob/v2.5.1/aten/src/ATen/native/cuda/BinaryDivTrueKernel.cu
    Triton 2.1 的 math 与较新版 libdevice 导入位置均有兼容分支。

P2a:
  PhaseKV/kernels/segmented_plan.py：描述表 valid_count 与容量分离，增量追加冷块；
    scratch 使用容量 stride，attention/merge 只遍历有效 partial。
    owner 列表保存 GPU 指针所引用的张量；页内追加及容量未满时指针保持稳定。
    stream、device、head、调度/开关变化重建；prompt 插入、重排明确失效。
    stream 同步仍由调用方负责，不承诺并发写安全。
P2b:
  PhaseKV/packed_storage.py：按 shape/bits/group/device 分池、固定槽位页；
    K/V 仍分别按原组量化，16-token 冷块没有合成 32-token 量化组。
  PhaseKV/phasekv_cache.py：冷区直接写页槽、所有者枚举、存储去重、重排重建池。
  models/packed_runtime.py：实际 KV 包含全部页及热区容量；另报有效码、元数据、
    空闲容量和辅助工作区。KIVI 分支不变并有回归验证。
  scripts/audit_kv_storage.py：新增 --optimized 独立实际容量审计入口。

P3:
  segmented_plan.py / segmented_attention.py / launch_config.py：
    cold_group=4/8/16 实验，工作单元内逐段 online softmax，最终写一个 partial；
    prompt 仍能 split，每个段使用自己的码和 scale/min。短 cold 回退 group=1。
    有效行数作为运行时值，避免每次增加 cold 都因该计数重新 JIT。
    分组当前为显式实验选择，没有在无 GPU 数据时声称选出了最佳占用率配置。

P4:
  segmented_attention.py：固定 4-bit shift/mask 与兼容布局检查；
    仅 prompt K32/cold K16/V32 进入专用路径，其余混合位宽/组长走通用路径。
    GQA 作为独立开关，多个 query lane 共享表达式中的 KV 读取/反量化；
    编译器实际寄存器、访存和占用率必须在 GPU profiler 检查，未声称读取减半。
    不修改 FP32 累加、exp 或 enable_fp_fusion=False。

P5:
  phasekv_cache.py：hot_start/hot_len 管理环形区，写入与冷却均不移动保留的热区。
    quantize_into 可以直接读取环绕的冷却批；decode_keep_ratio<1 只整理冷却批
    供原选择逻辑使用。多轮 prompt 扩容/冻结允许一次按逻辑顺序整理。
  segmented_attention.py：直接按底层 hot buffer + start + len 读取。
  hot_views/hot_range 是参考/调试有序取数接口，环绕时可分配拷贝；实际 CUDA
    decode 不调用它。attention_triton.py 旧参考路径和 benchmark_4090d.py 的
    oracle 已通过该接口取数，所以不需要修改模型 adapter 或评分代码。

公共开关与默认行为
==================
PhaseKV/optimizations.py 定义 OptimizationConfig，参数可直接传给
PhaseKVCache.from_dense_prefill(..., optimizations={...}) 或共享 build_phasekv_cache。
  fused_quantize=False       P1
  reuse_workspace=False      P2a
  paged_cold=False            P2b
  page_slots=32              存储容量参数；不改变冷却批或量化组
  cold_group=1               P3；允许 1/4/8/16
  specialized_4bit=False     P4
  gqa_reuse=False            P4 独立实验
  hot_ring=False             P5
stage_configs() 返回 baseline/p1/p2a/p2b/p3/p4/p4_gqa/p5 累积配置。
p5 基于 p4，不自动开启 gqa_reuse，避免未测收益的实验影响默认推荐。
P1 或单独分页不会切换 attention 内核。segmented_baseline.py 是原始内核文件
的字节相同副本；所有 attention 优化关闭时使用它。
src/phasekv 继续转发到 PhaseKV，没有复制另一套优化算法。

远程 Linux / RTX 4090 D 运行
===========================
依赖沿用项目现有 Torch/CUDA/Triton/Transformers 环境，不要求替换模型权重。
上传 ZIP 后在已有 /root/KV/PhaseKV 工程中展开；它是增量包，不包含模型和数据。
输出目录必须全新，禁止复用 reports/、sweep_result/、prompt_reset_result/ 或旧结果。

完整运行（先 GPU 功能测试，再微基准，再同轮完整质量与性能）：
  cd /root/KV/PhaseKV
  bash run_phasekv_optimizations.sh /path/to/Qwen2.5-7B-Instruct results/phasekv_opt_remote_001 full
只跑 GPU 功能及短矩阵：
  bash run_phasekv_optimizations.sh /path/to/Qwen2.5-7B-Instruct results/phasekv_opt_smoke_001 smoke
--require-cuda 会在没有真实 CUDA/Triton 时直接拒绝，不把跳过当作 GPU 通过。
初次 GPU 编译或数值失败时停止，保留日志，修复后换新目录，不扩大容差。

独立运行与消融示例：
  python scripts/test_phasekv_optimizations.py --require-cuda --output results/phasekv_opt_remote_002/tests.json
  python scripts/bench_phasekv_optimizations.py --output results/phasekv_opt_remote_002/micro.json
  python scripts/analyze_phasekv_optimizations.py results/phasekv_opt_remote_002/micro.json --output results/phasekv_opt_remote_002/micro.txt
  python scripts/bench_phasekv_optimizations.py --stages baseline p5 --overrides '{"fused_quantize": false}' --output results/phasekv_opt_no_p1/micro.json
  python scripts/bench_phasekv_optimizations.py --stages baseline p3 --overrides '{"cold_group": 16}' --output results/phasekv_opt_group16/micro.json
  python scripts/bench_phasekv_optimizations.py --stages baseline p2b --overrides '{"page_slots": 8}' --output results/phasekv_opt_page8/micro.json

微基准固定 query/张量/seed，轮次交替顺序、至少3轮，预热后提供事件及同步 wall time。
报告 prefill_pack、cold_pack、decode、attention、merge、描述表增长、完整
append→attention→cooling、finish_decode_step、独立 hot clone/copy 成本。
保留原始各轮数值和中位数、普通/冷却步 p50/p95、误差分布、partial 数、
scratch bytes、页面容量及浪费、峰值 allocated/reserved。
微基准为便于 A/B 同时持有各版本缓存，因此其绝对峰值包括比较器；temporary
delta 与每个 cache 的实际容量单列，端到端峰值由模型评测提供。
完整默认矩阵包含指定 prompt、cold、hot 数量及 GQA/MHA；p5 还从137位置环绕。

详细 profiler 单独运行，不向正式微基准混入 profiler 开销：
  python scripts/bench_phasekv_optimizations.py --profile --stages p3 p4 p4_gqa --prompts 1024 --cold-counts 128 --hot-lengths 128 --head-layouts 28:4 --output results/phasekv_opt_profile/trace.json
该模式输出 trace-only JSON 和 Chrome trace，不写正式速度中位数。
Nsight Compute 可对同样的单形状命令执行 --set full，核对寄存器、occupancy
与内存流量。微基准同时记录可取得的编译器 n_regs/n_spills/shared 元数据。

独立的完整模型逐步延迟诊断（与正式吞吐分开）：
  python scripts/trace_phasekv_optimizations.py --model-path /path/to/Qwen2.5-7B-Instruct --stage baseline --prompt 1024 --tokens 4096 --output results/phasekv_opt_trace/baseline.json
  python scripts/trace_phasekv_optimizations.py --model-path /path/to/Qwen2.5-7B-Instruct --stage p5 --prompt 1024 --tokens 4096 --output results/phasekv_opt_trace/p5.json
该诊断记录模型前向到冷却结束的事件时间及冷却步 p50/p95；host_submission_ms
只是异步提交时间，不能误写成同步 wall time。诊断中的吞吐不参与正式排名。

完整同轮评测：
  python scripts/compare_phasekv_optimizations.py --model-path /path/to/Qwen2.5-7B-Instruct --repeats 3 --out results/phasekv_opt_e2e_001
  python scripts/compare_phasekv_optimizations.py --model-path /path/to/Qwen2.5-7B-Instruct --repeats 3 --out results/phasekv_opt_e2e_001 --resume
仅相同源码/参数/模型/数据指纹允许续跑。修改任何开关后必须换输出目录。
脚本复用既有 compare_phasekv_same_round/retest_phasekv_prompt/benchmark_4090d：
Full-native、Full-matched、KIVI、SnapKV、SCOPE 配置不变，加入保存的 PhaseKV
基线和逐阶段版本；最终 p5 使用 PhaseKV 标签进入既有五算法报告。
保留每样本 prefill logits/首 token 审计、同文档配对、任务等权统计、QA/摘要
分开、逐任务/长度与配对区间；新增 optimization_ablation.json 对比保存的基线。
--quick 只是缩小质量矩阵，不能当作完整验收。4096输出仍只用于性能。

仍待远程完成的验收
==================
所有 CUDA 原始码/FP16 元数据字节一致性；内核编译和数学 oracle；
P2/P3/P4/P5 在真实 GPU 的 stream/容量/环绕边界；各阶段耗时与尾延迟；
P4 寄存器、占用率、GQA复用得失；Qwen7B 九形状性能和完整 LongBench 质量。
任何一项失败都应定位并修复，不能使用 CPU 通过、解释器运行、理论运算数
或平均加速数代替，也不能据此自动开启默认优化。
