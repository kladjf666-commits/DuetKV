# PhaseKV 在 A800 与 RTX 4090 上的解码性能

同一批输入、同一个 Llama-3.1-8B-Instruct，旧 PhaseKV 在 RTX 4090 上超过了 Full，在 A800 上却落后。A800 分项实测给出了直接原因：压缩缓存每步节省约 9.7–9.8 ms 的维护时间，但旧压缩注意力比 Full 的 FlashAttention 多用约 12.1 ms。把 4-bit prompt 的乘加改为 SM80 的 Tensor Core 矩阵乘累加后，B3 实测追回 3.54–3.83 ms/步，足以反超 Full。

## 同一负载换卡后，谁变快了

下表是整个 batch 的解码吞吐，单位为 token/s，越高越好。B3 指三条请求并行。Full 使用 FP16 稠密 KV 和 FlashAttention 2；这里的两个 PhaseKV 版本均保留 100% prompt 位置，prompt 和冷区采用 4-bit，冷却时从 16 个位置保留 13 个。

| 输入 + 输出 | 显卡 | Full | 旧 PhaseKV | 旧版相对 Full | 新版 PhaseKV | 新版相对 Full |
|---|---|---:|---:|---:|---:|---:|
| 9192+256 | RTX 4090 | 93.32 | 105.00 | +12.51% | 未测 | — |
| 9192+256 | A800-SXM4-80GB | 103.13 | 95.70 | −7.20% | 105.59 | +2.39% |
| 8192+2048 | RTX 4090 | 94.34 | 106.49 | +12.89% | 未测 | — |
| 8192+2048 | A800-SXM4-80GB | 103.36 | 96.11 | −7.01% | 109.05 | +5.50% |

以 8192+2048 为例，换到 A800 后，Full 从 94.34 升到 103.36，旧 PhaseKV 从 106.49 降到 96.11。两条实现对换卡的反应不同，性能名次因此翻转。两次 B3 的输入哈希、模型、精度、保留策略和主要软件版本一致；4090 是一次预热加一轮正式计时，A800 是一次预热加三轮正式计时取中位数。4090 的这一组数据来自 RTX 4090，不能用早期 4090D 的结果替代。[4090 原始记录](../PhaseKV与Full消融/4090_batch2_6_fAryLQ4D/summary.json) · [A800 旧版与 Full 原始记录](../PhaseKVA800测试/与其它算法的对比/a800_formal_v1/) · [A800 新版完整解码记录](../PhaseKVA800测试/与Full消融/a800_phasekv_mma_to_cutoff_v1/summary.json)

## A800 的差距发生在哪里

测量使用三条 8192-token 输入，在同一次生成内分别观察两个 16 步窗口。表中差值均为 PhaseKV 减 Full，正值表示 PhaseKV 多用时间。

| 解码步 | 无插桩端到端差值 | 注意力差值 | 缓存维护差值 |
|---|---:|---:|---:|
| 137–152 | +2.35 ms/步 | +12.11 ms/步 | −9.66 ms/步 |
| 265–280 | +2.06 ms/步 | +12.05 ms/步 | −9.81 ms/步 |

第 265–280 步，Full 的缓存更新占 10.35 ms/步，FA2 注意力占 2.74 ms/步。旧 PhaseKV 的描述表、热区追加和步末维护合计约 0.55 ms/步，读取压缩 KV 的主核占 14.28 ms/步，合并局部结果约 0.51 ms/步。分项使用 CUDA 流上的时间区间，可能含主机发射空隙；端到端使用另一次无插桩测量。两窗口的最大计时扰动分别为 3.07% 和 3.36%，不宜把分项直接相加当作无插桩总耗时。[分项计时与原始单位](../PhaseKVA800测试/与Full消融/a800_reason/20261104_181355_7052/summary.json)

另一个对照是在同一张 A800 上，让旧 4090 驱动循环和正式 A800 循环分别调用同一实现。两种循环产生相同的逐行输出哈希和相同的最终 KV 字节数。正式循环下，旧 PhaseKV 比旧循环快 0.009 ms/步，Full 快 1.035 ms/步。循环变化扩大了 Full 的相对优势；即使两者都用旧循环，PhaseKV 仍为 30.046 ms/步，Full 为 28.776 ms/步，差距依然存在。[同卡驱动循环对照](../PhaseKVA800测试/与Full消融/a800_reason/20261104_181355_7052/summary.json)

### 跨卡归因的边界

减少 KV 字节数有利于降低读取成本，但每一步仍要解包、恢复比例和偏移、计算点积、更新 softmax，再归并结果。RTX 4090 与 A800 上，稠密 FA2 和这条自定义 Triton 路径所用的指令与执行资源组合不同，压缩收益与计算开销可以在不同卡上出现不同的平衡点。A800 的分项计时及更换主核后的对照支持上述软件路径解释。当前缺少同协议的 4090 分项、显存带宽利用率、L2 命中率和寄存器停顿计数，因此没有依据把跨卡差距定量归因于其中某一项。A800 实测计算能力为 8.0，新路径显式检查这个条件。[A800 实验记录](../PhaseKVA800测试/与Full消融/a800_prompt_mma/20261104_183158_7407/summary.json) · [NVIDIA 对计算能力和指令支持的说明](https://developer.nvidia.com/cuda/gpus)

## 主核改了什么

1. **旧版如何处理 prompt。** 每个程序块负责一个 KV 头的一段位置，对共享这个 KV 头的多个查询头复用读取结果。对本次头维 128 的默认配置，旧路径每次处理 8 个 token，在片上解包 4-bit K/V，广播乘法后用 `tl.sum` 完成 QK 点积和对 V 的加权求和，每小块更新一次在线 softmax。简单增大旧 tile 的回放结果反而更慢，单开 FMA 对每层主核加合并的改善不足 1%。[旧路径与 tile 对照](../PhaseKVA800测试/与Full消融/a800_reason/20261104_181355_7052/summary.json)
2. **新路径怎样计算。** `_a800_segmented_attention` 沿用现有 prompt 分段和描述表。每次读入 64 个 token，直接从已有的通道连续布局解包 K/V，在片上处理量化比例和最小值。每个 KV 头对应的 4 个真实查询头放入 16 行矩阵，屏蔽其余行的读写。用两次 `tl.dot` 分别计算 QKᵀ 和 softmax 权重乘 V。矩阵乘数使用 FP16，最大值、分母及输出累加使用 FP32；跨块依旧通过最大值重标定来稳定 softmax。整份 KV 无需展开成常驻 FP16 副本。[主核源码](PhaseKV/kernels/segmented_attention.py)
3. **只在满足条件时分派。** 开关为 `optimizations.a800_prompt_mma`，默认关闭。启用后，还要满足 SM80、兼容的 4-bit 描述表、通道连续 K、GQA 复用、4 个查询头共享一个 KV 头、头维 128。符合条件的 prompt 分段走新分支；冷段和热环继续复用已有实现，各段输出仍由原合并核归一化。每层仍是主核加合并两次发射。保留位置、选择算法、缓存位数和 RoPE 绝对位置均由原缓存逻辑决定。[开关定义](PhaseKV/optimizations.py) · [缓存实现](PhaseKV/phasekv_cache.py)

## 修复效果

抽取第 0、10、20、31 层的真实输入，在同一 A800 上回放。主核从 0.444 降到 0.326 ms/层，合并前后均约 0.010 ms/层。按主核加合并的配对结果，0.454 降到 0.338 ms/层，折算 32 层约省 3.71 ms/步，与两个端到端窗口实际节省的 3.83 和 3.54 ms/步接近。两个窗口的吞吐均超过同轮 Full；三个输入在逐步贪心回放中均与旧 PhaseKV 一致。[四层回放与端到端 A/B](../PhaseKVA800测试/与Full消融/a800_prompt_mma/20261104_183158_7407/summary.json)

正式截点复测中，新版在 18 个点中有 16 个超过 Full。9192+256 的 B8 为 190.72 对 154.18 token/s，8192+2048 的 B8 为 181.98 对 152.32 token/s。约 8K–9K 的两个 B1 负载仍慢于 Full；32768+256 的 B1 则领先 14.00%。这次验证的是全保留 prompt 的固定生成长度吞吐。缩小 prompt 后的速度和真实任务答案质量由下面的补测单独验证。[18 点结果](../PhaseKVA800测试/与Full消融/a800_phasekv_mma_to_cutoff_v1/summary.json)

## 512 位置与 25% 预算补测

输入长度 9192 时，PhaseKV 保留 25% 对应 2298 个位置，固定 512 对应约 5.57%。历史 PyramidKV 的 32 层从底层 991 到顶层 33，平均恰好 512，采用 FP16；PhaseKV 每层保留相同数量的 4-bit 位置。相同位置预算与相同字节预算是两种比较。历史 B8 的 377.71 token/s 只反映吞吐，所用重复文本没有可用的答案标签。[PyramidKV 实际逐层长度](../PhaseKVA800测试/与其它算法的对比/a800_formal_v1/pyramidkv/speed/9192+256_B8_r3.json)

### 先跑初筛

初筛只占用一个 B8 速度点和一次 B1 质量生成。上传[离线初筛与正式实验包](../PhaseKVA800测试/与Full消融/PhaseKV_A800_budget512_quick_v1.zip)到服务器 `/data` 后运行

```bash
cd /data &&
unzip -oq PhaseKV_A800_budget512_quick_v1.zip &&
bash /data/a800_budget512_quick_v1/run.sh quick
```

- **速度**。在同一组 9192+256 的 8 条输入上，只测新版 PhaseKV 每层固定保留 512 个 prompt 位置。沿用正式计时的 1 次预热和 3 次测量。看 `speed.tps` 与同环境历史 PyramidKV 的 377.71 token/s 相差多少。PhaseKV 保留 25% 会留下 2298 个位置，留到完整实验。
- **质量**。按输入长度与 9192 的距离预选 48 条中最近的样本，即 LongGenBench MMLU 第 30 号复合输入。它有 10903 个输入 token 和 30 道子题，PyramidKV 平均留 512 个位置，使用原始停止条件和 4096 个输出 token 上限。历史 RTX 4090 D 的 Full 在相同输入上按题号答对 16/30。运行时复核输入哈希并重新评分。如果结果目录已有同一 A800 的 Full 答案，则优先与它配对。
- **读结果**。`/data/phasekv-results/a800_budget512_v1/quick_summary.json` 中，`quality.pyramid_minus_full_pp` 是 PyramidKV 相对 Full 的按题号准确率差，单位为百分点。`lost` 与 `gained` 分别记录 Full 答对而 PyramidKV 答错、以及反向变化的题数。`full_source` 标明对照的 GPU。30 道子题共享一条上下文，结果只能作为该条输入的初筛信号。

### 再跑完整实验

保留初筛结果目录，下面的完整实验会接着跑，跳过已有的速度点和质量生成。正式质量比较在同一 A800 上按题配对。历史 4090 D 的 Full 答案只用于初筛。

| 阶段 | 配置与输入 | 结果 |
|---|---|---|
| 速度 | 新增 PhaseKV 固定 512、PhaseKV 25%。相同 8 条输入，9192+256，每点预热 1 次、计时 3 次 | 总解码吞吐中位数、TTFT、最终 KV、峰值显存、各层实际保留数；同环境下对照历史 Full、PhaseKV 100%、PyramidKV 512 |
| 质量 | Full、PyramidKV 平均 512、PhaseKV 固定 512、PhaseKV 25%、PhaseKV 100%。B1 独立贪心生成，沿用每条的停止 token 与 4096 个生成 token 上限 | 官方得分、按题号准确率、未解析或漏答题数、相对 Full 的得失题数与净百分点、循环重复诊断 |

质量集有 GSM8K、CSQA、MMLU 各 16 条复合 prompt，共 1600 道子题，五个配置共 240 次生成。48 条输入的 ID 与 token 哈希已与 4090 保留率扫描逐条核对。25% 按每条输入独立计算，因而在短于 2048 的质量样本上可能比固定 512 留得更少。按题号准确率以全部期望子题数为分母，未解析答案计错；配对差异仅统计双方均成功并且输入哈希一致的 prompt。OOM 独立计数。严重循环沿用旧规则，即到达生成上限、没有解析出任何答案且同一答案标题至少出现 100 次；另存最长连续相同 token 数，便于排查单 token 循环。[历史质量扫描](../PhaseKV与Full消融/4090_prompt_quality_scan/summary.json)

安装包自带测试代码、评分器和输入，复用服务器已有的主环境及模型权重。测速预热要求 32 层、255 个解码步都实际走 MMA 主核。对 B8 的部分保留路径，先从末尾观察窗口选出各请求、各 KV 头的下标，再以同一顺序折叠 KV 和下标。每次运行核对各层实际长度与完整 prompt 的绝对位置。
