PhasekKV-code 的 Prompt90 同卡峰值显存与速度快速对照 v1
2026-11-07

本目录的有效源码是顶层 PhaseKV/。benchmark/ 中的独立入口明确加载它。

本轮保持：Prompt90%、冷却块目标80%（16取13）、Prompt/冷KV均INT4、
recent128、obs32、group32、sink0，以及原A800 MMA/GQA/热环等开关。
不改变解码内核、选择规则、量化规则、RoPE绝对位置或质量输入/输出上限。

实现变化
1. PhaseKV/memory_prefill.py：每层观察尾部算完立即提取原规则的选中位置。
   不再让LlamaModel收集32层完整注意力权重，只跨层保存位置下标。
2. PhaseKVCache.from_dense_prefill 增加显式 consume_dense_cache 选项。
   优化入口逐层量化后清空源K/V列表项；默认False保持原调用约定。
3. Batch展开直接更新被移交的缓存，避免另一个视图列表继续引用旧显存。
4. 质量仍使用原来的一次完整前缀调用；速度仍使用512-token分块前缀。

这是张量生命周期优化。完整FP16前缀KV仍要建立，不能保证峰值降到解码水平。
本地仅CPU；未宣称已测得A800峰值下降或吞吐提升。CUDA门禁失败即停止。

快速测试范围
每个速度点：同一模型、同一GPU、两条路径（baseline/optimized），
每条路径预热1轮、正式3轮。逐轮交替先后顺序；预热不计成绩。
优先：32768输入 + 256输出，Batch8，先拿到高峰值场景结果。
其次：8192输入 + 256输出，Batch1，检查常规输入速度。
最后：32768输入 + 2048输出，Batch1，检查长生成与冷却维护开销。
合计3点×2路径×3正式轮=18正式轮，正常首次运行另有6轮预热。
没有测试32768+2048/B8，不将256输出的解码结果冒充2048输出结果。

质量仅2条回归样本、每路径各跑一次：
- LongBench qasper，完整8074-token输入，原cap128，允许自然EOS。
- RULER cwe/32k/5，完整32599-token输入，原cap120，允许自然EOS。
合计4次质量生成。它们用于检查输出一致性，不是全套质量重评估。

CUDA门禁（不计入正式速度）
- quality/B1、speed/B1、speed/B8：相同2112-token输入、164-token生成。
- 两路径首token logits严格一致，打包Prompt KV的码/scale/min字节一致，
  生成token一致；检查32层实际保留数、位宽、Batch头布局和绝对位置。
- 经过两个冷却块及热环绕回；B8合成分段注意力核对反量化参考。
正式速度和2条质量结果也检查逐token哈希一致；不一致停止，不放宽门槛。

时间：按历史耗时估计约20–30分钟，模型加载/JIT和设备状态可能延长。
32K/B8排在最前，完成两条路径预热后即可在日志看初步峰值；正式结论看3轮。
只用一张A800 80GB；不重装环境，不重新上传模型，不修改原测试包/结果。

上传
将 deliverables/a800_bettermemory_quick_v1.tar.gz 和同名.sha256 上传到 /data。
新目录 /data/a800_bettermemory_quick_v1 应不存在；若已存在，不要覆盖。

cd /data
sha256sum -c a800_bettermemory_quick_v1.tar.gz.sha256
test ! -e /data/a800_bettermemory_quick_v1 && tar -xzf a800_bettermemory_quick_v1.tar.gz
python3 /data/a800_bettermemory_quick_v1/benchmark/runner.py prepare

后台启动
nohup bash /data/a800_bettermemory_quick_v1/run.sh run --gpu 0 > /data/a800_bettermemory_quick_v1/launcher.log 2>&1 < /dev/null &

查看
tail -n 30 -F /data/phasekv-results/a800_bettermemory_quick_v1/run.log
python3 /data/a800_bettermemory_quick_v1/benchmark/runner.py status

若prepare失败，先查看报错；不会加载模型或自动安装依赖。
默认复用 /data/phasekv-results/a800_quality_fulltext_v1/config.json 中的
模型、main环境和 /data/phasekv_a800_4gpu_v1 冻结运行时，逐文件核对manifest。
原始checkpoint大小/时间戳及模型元数据、软件版本均核对。
第一次绑定物理GPU UUID；断点续跑必须同一GPU。不会停止其它进程。

中断后重用相同启动命令：跳过已提交质量与正式轮，未完点重新预热。
已有OOM/error不会自动重跑，需要先查日志。已全部完成则run不加载模型。
原有结果保持原位置；本次新输出只有 /data/phasekv-results/a800_bettermemory_quick_v1。

结果
summary.txt / summary.json：逐点A/B吞吐、每请求速度、TTFT、端到端吞吐、
最终KV、prefill/decode/整轮峰值及百分比变化。速度/最终KV取3轮中位数，
峰值取3轮最大值。失败与未完成不填0。峰值是PyTorch allocated，包含权重。
quality/：2样本×2路径的生成文本、逐token输出、评分、显存与原输入身份。
speed/：18个逐轮记录；warmups/：预热；gates.json：CUDA门禁证据。
plan.json / protocol.json / gpu.json：数据、代码、环境、模型与GPU身份。
