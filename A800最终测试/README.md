# A800 最终测试：目录与文件说明

本目录保存最终采用的 A800 测试结果，包括峰值显存优化前的 Prompt90、优化后的 BetterMemory，以及其它算法的最终对照。历史中间测试和上传压缩包已清理。

清理后新增的 `TTFT同卡复测_20261107/` 保存两个测点的同卡A/B验证。该复测未复现大幅TTFT退化，独立于原16点性能结果；其回传压缩包和校验文件也保留在本级目录。

## 3. BetterMemory_速度与峰值显存

这是本轮最终保留的 BetterMemory 性能结果。测试矩阵为输入长度 `8192 / 32768`、每请求输出长度 `256 / 2048`、Batch `1 / 2 / 4 / 8`，共 **16个测点**。每点保留3轮正式测量和1轮预热。

### 子文件夹

| 文件夹 | 内容与用途 |
|---|---|
| `逐轮记录/` | 48个 JSON，每个文件是一轮正式测量。保留总吞吐、单请求吞吐、解码耗时、prefill/decode/整轮峰值、参数及输入输出哈希等，用于复核统计。 |
| `预热记录/` | 16个 JSON，每个测点一条预热记录；不计入正式成绩。 |
| `实验身份/` | `gates.json` 保存 B1/B2/B4/B8 等正确性检查；`state.json` 保存运行开始、结束和完成状态。 |
| `图表/` | `01_解码总吞吐`、`02_端到端吞吐`、`05_首token等待对比`（仅其它算法），每图有 PNG 和 SVG 两种格式。整轮峰值图放在本级目录。 |

### 本级主要文件

| 文件 | 内容 |
|---|---|
| `结果查验与分析.txt` | 完整性检查、16点性能表、与优化前的比较及解释。 |
| `速度与峰值汇总.json` | 本轮16点的总/单请求/端到端吞吐、各阶段峰值、轮数及 GPU 信息。 |
| `全部算法速度与峰值对比.json` | BetterMemory、优化前 Prompt90 与历史算法的性能汇总，适合进一步制表或绘图。 |
| `峰值汇总.json` | 仅含本轮峰值显存的独立汇总表。 |
| `峰值对比.json` | BetterMemory 与优化前、历史算法的峰值对照数据。 |
| `全部算法峰值对比.png` / `.svg` | 全部算法的整轮峰值显存对比图。 |
| `实验身份.json` | 模型、参数、软件版本、GPU、实验标识及原始来源哈希。 |
| `阅读说明.txt` | 此文件夹的简版说明。 |

速度取3轮正式测量的中位数；各项峰值取3轮中的最大值。本目录的逐轮文件是清理时提取的测量记录，保留速度和峰值原值及来源哈希，未保留本轮最终 KV 大小或生成文本。**本轮没有新增完整质量评估**，正确性检查不能代替完整任务质量测试。

## 5. 多算法最终对照

### 八个算法文件夹

每个算法有432条质量处理记录；记录包含成功和失败状态，并非每个算法都成功完成432条。

| 文件夹 | 算法 | 质量记录状态 | 16点速度矩阵中的状态 |
|---|---|---|---|
| `full/` | Full，完整稠密 KV 基线 | 432成功 | 16成功 |
| `phasekv/` | 较早 PhaseKV 对照组 | 432成功 | 16成功 |
| `kivi/` | KIVI | 432成功 | 16成功 |
| `clusterkv/` | ClusterKV | 425成功、7不支持 | 4个B1点成功；其余12点未安排 |
| `snapkv/` | SnapKV | 432成功 | 16成功 |
| `pyramidkv/` | PyramidKV | 432成功 | 14成功、2 OOM |
| `million/` | MILLION | 432成功 | 4个B1点成功；其余12点未安排 |
| `scope/` | SCOPE | 298成功、134 OOM | 4成功、12 OOM |

本级的 `覆盖数.json` 保存上述状态统计。`OOM` 表示显存不足，`unsupported` 表示不支持，`not_tested` 表示没有安排测试；这些状态均不等于得分为零。

### 每个算法内部的共同结构

以下说明适用于上表中的全部八个算法文件夹：

```text
<算法>/
├── 实验身份/
│   ├── protocol.json                实验协议和配置
│   └── gate.json                    运行前正确性检查
├── 速度原始记录/                    各测点汇总；成功记录含三轮runs
└── 质量原始记录/                    三套数据集的逐题记录
    ├── longbench/                   320条完整输入质量处理记录
    ├── longgenbench/                48条长生成复合题处理记录
    └── ruler/                       64条约32K输入的检索等任务记录
```

`速度原始记录/` 中的文件名如 `32768+2048_B8_r3.json`，表示32768输入、2048输出、Batch8、三轮汇总；成功记录中的 `runs` 保存各轮测量，OOM记录保存失败状态。ClusterKV 和 MILLION 各只有4个B1文件。

### 分析与图表

此文件夹保存原始八算法的汇总分析，当前没有独立 PNG/SVG 图文件。要找图，优先查看 Prompt90 和 BetterMemory 的图表目录。

| 文件 | 内容 |
|---|---|
| `最终结果报告.txt` | 完成情况、质量、速度、显存、覆盖率与比较口径的主报告。 |
| `analysis.json` | 八算法结构化汇总分析。 |
| `failures.json` | 失败样本和配置的明细。 |
| `score_recheck.json` | 根据保存预测复算得分的核验结果。 |
| `最终KV缓存大小.txt` | 各算法生成结束后的 KV 缓存占用；与运行过程中的峰值显存是不同指标。 |

### SnapKV质量分层

`结果说明.txt` 和 `analysis.json` 对已有完整输入预测进行离线分析，按输入长度、任务分组，并与 Full 做同题配对比较；没有新增 GPU 推理。这里引用的 PhaseKV90 质量仍来自优化前结果。

RULER 两项 NIAH 任务的 SnapKV 原配置为1024预算，VT/CWE为2048，不能将全部质量样本统一标为“SnapKV2048”。

## 6. 读数与追溯

- `8192+256_B4` 表示每条请求8192输入、256输出，4条请求并行。总解码吞吐与单请求速度分开统计；TTFT为首 token 等待时间，端到端吞吐还计入预填充耗时。
- 峰值显存采用 PyTorch allocated 口径，包含模型权重、KV及临时张量；最终 KV 大小仅指生成结束后保留的缓存，两者不要混用。
- 质量测试采用选定子集的完整题面、各任务原输出上限和自然 EOS，并非官方全量数据集。固定长度测速使用工程文本，其输出不能直接作为任务质量成绩。
- 不同轮次使用的 GPU 与历史并发条件存在差异。跨目录速度比值是已有记录的观测比较，不能直接作为同卡、同条件受控加速比。
- 原始报告和 JSON 保留了实验当时的路径、压缩包名及文件数；其中提到的旧截断样本、中间结果和压缩包已清理。**当前目录保留范围以本说明为准**，迁移映射及哈希见项目根目录的[保留来源清单.json](../清理记录/保留来源清单.json)。

## 7. TTFT同卡复测_20261107

此目录是清理后新增的补充实验，不在此前清理快照中。只测 `8192+256/B1` 和 `32768+256/B8`，同一GPU、同一进程交替运行优化前Prompt90与BetterMemory。正式三轮TTFT与吞吐基本持平，32K/B8峰值仍下降27.34%。

| 位置 | 内容 |
|---|---|
| `结果查验与分析.txt` | 中文完整性核验、正式指标、逐轮配对、分段诊断和结论。 |
| `analysis.json` | 独立重算的汇总、变化百分比、分段数据和遥测范围。 |
| `results/` | 回传原始结果总目录；本级有 `summary.txt/json`、`protocol.json`、`plan.json`、`gpu.json`、`state.json`及`run.log`。 |
| `results/pairs/<场景>/` | 每场景 `r1.json` 至 `r3.json`，共6个A/B配对文件，每个内含两条正式测量，共12条。 |
| `results/diagnostics/` | 两个诊断配对文件，共4次额外预填充；记录前缀、观察窗口/选择、布局、量化打包和首token阶段，不计入正式统计。 |
| `results/warmups/<会话>/<场景>/` | 每场景的baseline和optimized预热记录，共4条，不计成绩。 |
| `results/gates/` | 本轮进程的B1/B8正确性门禁及冷却/热环参考检查。 |
| `results/checkpoint_io/` | 计时区间之外的状态和检查点写盘耗时。 |
| `test_package/` | 实际运行包的33个文件，已与交付包逐字节核对。其 `PhaseKV/`（含 `kernels/`）为核心源码，`benchmark/`为控制与诊断代码，`data/`为输入及身份，`tests/`为本地验证；本级另有说明、运行入口、验证记录和SHA256清单。 |

本轮CUDA分段数据来自单次插桩诊断，包含CPU提交间隙的可能性；位置选择已包含在观察窗口与选择合计中，不能重复相加。结论仅覆盖本轮两个点，不以它们替换或拼接原16点结果，也不代表新增完整任务质量评估。

## 8. 旧TTFT清理说明

按用户要求，旧PhaseKV、Prompt90及BetterMemory的TTFT字段与相关比较已清理；其它算法TTFT及所有质量、解码/端到端速度、显存指标保留。PhaseKV的TTFT仅采用TTFT同卡复测_20261107中的两个测点，不补齐或拼接成16点成绩。

历史PhaseKV系列JSON现为移除TTFT后的记录，目录名称中的“原始记录”沿用原名。最新复测results/、test_package/及回传压缩包保持原字节；其它算法独立结果目录也未修改。旧来源哈希表示清理前版本，本次文件指纹和校验见 `清理记录/PhaseKV旧TTFT清理_20261107/`。
